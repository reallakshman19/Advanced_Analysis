## Authority architecture

### Professional release-state authority owner

`emp1-professional-release-state-authority.js` freezes the only release-current-state artifact admitted by this slice:

- path: `validation/emp1/release/emp1-professional-release-current-state-v1.json`
- Git blob SHA-1: `8d108c6f7850e2a240fc15fdd51318ce1a70a29f`
- semantic hash: `f9a205509b0da61014655bdb7271c5f4d5716a36a40ab3ea11e0a6cbab286d81`

It additionally freezes the critical authority/scope fields carried by that artifact. A caller cannot substitute a self-consistent release-state object with different authority booleans.

### Engineering Record qualification binding

`emp1-engineering-record-release-qualification.js`:

1. validates the Engineering Record package;
2. requires the exact frozen release-state artifact identity;
3. consumes the existing read-only release handoff projection;
4. requires `REVIEW_ACCEPTED` for release qualification;
5. creates a deterministic qualification-record identity;
6. may reflect release qualification only from the explicitly admitted release-state authority.

The current admitted release state has:

```text
professionalReleaseReady = false
releaseQualified = false
deploymentAuthorized = false
```

Therefore the expected current result is:

```text
RELEASE_BLOCKED_EXISTING_AUTHORITY
releaseQualified = false
```

A `REVIEW_REJECTED` Engineering Record remains an auditable package but is classified:

```text
RELEASE_BLOCKED_ENGINEERING_REVIEW_NOT_ACCEPTED
```

## Authority boundary

The qualification record is authoritative only as a binding between an exact Engineering Record and an exact admitted release-state artifact.

It explicitly does not:

- create the underlying release authority;
- let callers set `releaseQualified`;
- let callers substitute release-state authority;
- create deployment authority;
- create code-compliance authority;
- create source/method/applicability/numerical authority;
- create a cryptographic signature or professional seal.

Deployment remains a separate authority domain.

## Checker encoded

`node scripts/emp1-engineering-record-release-qualification-check.mjs`

The checker is designed to verify:

- the real retained release-state artifact's canonical semantic hash;
- the real retained release-state artifact's Git blob SHA-1;
- current accepted Engineering Record remains release-blocked;
- rejected Engineering Record cannot qualify;
- incompatible route/profile cannot qualify;
- forged release-state booleans/hash cannot qualify;
- wrong artifact path/blob cannot qualify;
- qualification-record tamper detection;
- no WRC execution/numerical/applicability authority or deployment/seal authority is introduced.

Execution remains `NOT_RUN`.
